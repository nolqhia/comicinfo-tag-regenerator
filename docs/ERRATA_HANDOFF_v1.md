## §A 実害級（実装前に必ず反映）

### A-1. 文字数制限と台帳の矛盾 → ルール改訂

seed_vocab の canonical に7文字以上が12語（ダークファンタジー, ハイファンタジー, メタフィクション,
ボーイ・ミーツ・ガール, 信頼できない語り手, ロードムービー 等）、pending に26語
（クローズドサークル, サイバーパンク, タイムトラベル, トランスジェンダー 等）存在する。
v4 の「上限6文字」を機械検証すると台帳の正規語自身を弾く。

**改訂ルール**: 文字数制限（2〜6文字）は**新規タグの生成時のみ**適用。
**台帳収載語（canonical / pending）は文字数制限の適用外**（確立したジャンル語・批評用語のため）。
検証器の違反条件は「台帳非収載 かつ 7文字以上」とする。

### A-2. Kavita フィールドロック問題（書き戻しが反映されない罠）

既存 Genres が Kavita UI での手動編集由来の場合、当該フィールドは**ロック**され、
ComicInfo.xml を書き換えてライブラリ再スキャンしても**上書きされない**。

**手順**:
1. 書き戻し前に、1シリーズで実験: ComicInfo 書換 → スキャン → Kavita UI で Genre が変わるか確認
2. 変わらない場合、Kavita API で `POST /api/Series/metadata` を叩き
   `genresLocked: false`（および必要なら genres を空に）へ更新してからスキャン
3. DTO のフィールド名はバージョン差があるため `/swagger` で実機確認すること
4. この検証を §7 の環境確認に **5番目の項目として追加**

### A-3. ZFS スナップショットを必須手順に追加

horreum は TrueNAS SCALE / ZFS。書き戻しバッチ開始前に:

```bash
zfs snapshot <pool>/<dataset>@pre-tag-regen-$(date +%Y%m%d)
```

これで .cbz 全体の完全ロールバックが常に可能。30 Series バッチは「作業粒度」、
スナップショットは「災害復旧」として役割が異なる。両方やる。

## §B seed_vocab / 正規化ロジックのパッチ

### B-1. 従姉・従姉妹→姉妹 の統合は**意味誤り**（いとこ≠姉妹）

`build_tag_ledger.py` 側ではなく finalize 段の extra_alias に混入していた誤り。
偽リンク（いとこ物語と姉妹物語の誤接続）を生むため修正必須。

**パッチ**:
- seed_vocab.json の pending に `"いとこ"` を追加
- 該当シリーズの特定は `ledger/tag_ledger.json`（finalize 前の状態を保持）の
  `pending["従姉妹"].series` / `pending["従姉"].series` から復元可能
- 以後の正規化規則: 従姉/従姉妹/従兄弟/いとこ → `いとこ`

### B-2. 複合ジャンルの片側成分喪失

`ALIAS` の以下2件は片側の情報を落とす。`DECOMPOSE` へ移す:

```python
# 誤: ALIAS
"Sfミステリー": "ミステリ",      # SF成分が消える
"ホラーミステリ": "ミステリ",    # ホラー成分が消える(finalize側)
# 正: DECOMPOSE
"Sfミステリー": ["SF", "ミステリ"],
"ホラーミステリ": ["ホラー", "ミステリ"],
```

series_normalized.json で該当シリーズの SF / ホラー が欠けている可能性があるが、
どのみち全再生成するため diff 時に「想定内差分」として扱えばよい。

### B-3. TS と 性転換 が未統合（両方 canonical）

同義対。`TS → 性転換` に統合する（alias 追加）。
ただし pending の `トランスジェンダー` は**別概念**（アイデンティティ）なので統合しない。

### B-4. discarded は「完全なブラックリスト」ではない

discarded 71語は本セッションで具体的に検出した個体にすぎない。
**禁止の実体はパターン**: ①作中人名 ②作中地名 ③作中造語・技名 ④書誌メタ（賞・刊行状態・頒布イベント）。
検証器は「discarded 照合 + パターンヒューリスティック（可能な範囲）」の二段にし、
最終防衛はパス2の推敲と diff 人間レビューが担う。discarded にヒットしない＝安全、ではない。

## §C パイプライン設計の確定事項（HANDOFF の曖昧部分）

### C-1. パス1後の頻度集計は seed と**マージ**（作り直さない）

- seed の canonical は維持（降格させない）
- seed の pending は、パス1で2件目が観測されたら canonical へ昇格
- パス1の新語は pending として追加
- ゼロベースで canonical/pending を引き直すのは誤り

### C-2. Tag_Prompt_v4 はチャット用。機械プロンプトを派生させる

v4 は対話仕様（口調・Amazon URL フロー・箇条書きテンプレート）を含む。
Ollama パイプラインには**規則部分のみを蒸留した2枚**を作る:

- `prompt_pass1.txt`: タグ哲学（接続＞想起）＋タグ仕様＋禁止パターン。
  **語彙リストは入れない**（アンカリング回避）。出力は `{"tags": ["…", ×10]}` の JSON のみ。
- `prompt_pass2.txt`: パス1の生タグ＋canonical 全語＋discarded パターンを注入し、
  揺れ矯正・固有名詞→実在語持ち上げ・複合語分解の推敲を指示。同じ JSON 出力。

お嬢様口調・前置き・検索指示はパイプラインに持ち込まない（Ollama は `format=json` を併用）。

### C-3. rezip 検証の具体化

「検証」の合格条件を明文化する:
1. エントリ数が一致（ComicInfo.xml の有無差分を除く）
2. ComicInfo.xml 以外の**全エントリの CRC が完全一致**（画像無劣化の証明）
3. 新 ComicInfo.xml が XML としてパース可能で `<Genre>` が期待値
4. 置換は tmp ファイルに書いて `os.replace()`（atomic rename）

### C-4. シリーズ→物理ファイルの対応は Kavita API 経由が確実

シリーズ名とフォルダ名の突き合わせは表記差で事故る。
Kavita API の series → volumes → files に filePath が含まれるため、そちらで .cbz の実パスを取得する。
